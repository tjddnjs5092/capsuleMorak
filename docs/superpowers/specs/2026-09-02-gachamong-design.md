# 가챠몽 (Gachamong) — 온라인 가챠샵 데모 설계 문서

- Date: 2026-09-02
- Status: Draft for review

## 1. 개요

온라인 가챠샵(가챠덕 등 참고)을 벤치마킹한 자체 브랜드 서비스. 지금 단계의 목표는
**실제 결제 없이 가상 재화로 동작하는 데모**를 만들어, UI·뽑기 인터랙션의 재미를
검증하고, 이후 법적 검토(결제/확률형 상품 표시 규제 등)를 거쳐 상용화할 수 있는
기반 구조를 갖추는 것이다.

- 실제 결제(PG)/실물 배송 없음 — 가입 시 지급되는 가상 캐시로 뽑기
- 계정/보유 아이템/뽑기 로그는 실제 DB에 저장 (로컬스토리지 아님) — 추후 결제
  연동 시 데이터 구조를 바꾸지 않고 확장
- 반응형 웹 1개 (모바일 브라우저 + 데스크톱 브라우저 대응, 네이티브 앱 아님)

## 2. 브랜드 아이덴티티

- **서비스명**: 가챠몽 (Gachamong) — 상표/도메인 중복 검색 결과 충돌 없음 확인
  (가챠덕, 가챠몰, 가챠냥 등 기존 서비스와 겹치지 않음). 단, 실제 출시 전
  특허청 상표 검색(키프리스)·도메인 확보는 사용자가 별도로 진행 필요.
- **마스코트**: 크림색 뭉게구름 형태의 오리지널 캐릭터. 짓궂고 능청스러운
  성격. 이름은 "몽글이" 사용 금지(카카오톡 펫 육성 게임과 명칭 충돌) —
  최종 이름은 몽몽이/몽이/뽀몽이 등 후보 중 확정 필요 (사용자 확인 대기).
- **저작권 유의사항**: 짱구(크레용 신짱), 365mc "지방이" 등 제3자 캐릭터의
  디자인·이름을 참고/재사용하지 않음. 마스코트 아트는 사용자가 AI 툴로
  직접 생성한 원본 이미지 사용.
- **뽑기 연출 영상**: 사용자가 AI 툴로 직접 생성한 원본 mp4
  (`video.mp4`, 동전 투입 → 캡슐 등장 → 흔들림 → 오픈 → 연기 → 마스코트
  등장 → 점프 → 인사 → 축하 빵빠레 → 결과 카드, 총 12단계 스토리보드)를
  프로덕션 에셋으로 사용. 브라우저 호환성을 위해 웹 최적화 인코딩(mp4/webm,
  압축) 필요. 저사양 기기·데이터 절약 모드 대비 CSS/SVG 기반 경량 애니메이션을
  폴백으로 유지 (프로토타입 단계에서 이미 구현됨).

## 3. 기술 스택

- **프레임워크**: Next.js (App Router) — 프론트엔드와 API를 한 코드베이스로
- **DB**: PostgreSQL + Prisma ORM
- **인증**: Auth.js (NextAuth) — 이메일/비밀번호 또는 소셜 로그인
- **배포**: 추후 결정 (Vercel 등) — 이번 스펙 범위 밖

이 구조를 선택한 이유: 지금은 결제 기능이 빠진 데모지만, 추후 국내 PG
(토스페이먼츠/아임포트 등) 연동 시 API 라우트만 추가하면 되고, 회원/보유
아이템 데이터가 처음부터 실 DB에 있어 구조 변경 없이 확장 가능하기 때문.

## 4. 핵심 화면 및 사용자 흐름

1. **홈** — 머신(가챠 상품군) 목록, 배너, 인기/신상 머신
2. **머신 상세** — 캡슐 라인업(등급별 확률 상시 공개), 잔여 수량, 보유 캐시,
   "1회 뽑기" / "5회 뽑기" 버튼
3. **뽑기 연출 화면** — 12단계 캡슐 오프닝 시퀀스 재생 → 등급 공개.
   일반/레어/슈퍼레어 등급에 따라 연출 강도(파티클/플래시) 차등
4. **보관함 (마이 캡슐)** — 보유 아이템 목록. 중복 아이템은 구매가의 50%를
   가상 캐시로 즉시 환급(가챠덕 벤치마킹)
5. **실시간 뽑기 피드** — 다른 유저의 뽑기 로그, 잭팟(슈퍼레어) 하이라이트
6. **로그인/회원가입** — Auth.js. 가입 시 테스트용 가상 캐시 자동 지급
   ("캐시 충전"은 실제 결제 없이 지급 버튼으로 대체)

Phase 2 (범위 밖, 추후 검토): 출석 체크(30일 캘린더), 친구 초대 리워드,
실제 결제 연동, 실물 배송.

## 5. 데이터 모델 (Prisma 초안)

- `User` — id, email, passwordHash, cashBalance, createdAt
- `Machine` — id, name, description, imageUrl, isActive
- `Item` — id, machineId, name, imageUrl, grade(등급), probability(확률),
  price, stock
- `PullLog` — id, userId, machineId, itemId, grade, createdAt (실시간 피드용)
- `InventoryEntry` — id, userId, itemId, acquiredAt, refundedAt?
  (중복 환급 시 기록)
- `Wallet`은 `User.cashBalance` 필드로 단순화 (별도 테이블 불필요, 데모 범위)

확률(`Item.probability`)은 등급별로 상시 공개 — 한국 확률형 상품 표시
규제 대응 원칙을 데모 단계부터 반영.

## 6. 뽑기 이펙트 사양

- 트리거: "동전 넣고 돌리기" 버튼 클릭
- 시퀀스(사용자 제공 영상 기준 12단계): 동전 투입 → 캡슐 데굴데굴 등장 →
  약한 흔들림 → 강한 흔들림 → 캡슐 오픈(빛 폭발) → 구름 연기 → 마스코트
  등장 → 풀 리빌(반짝 파티클) → 신나는 점프 → 인사(말풍선) → 축하
  빵빠레(색종이) → 결과 카드(등급/이름)
- 등급별 연출 차등: 일반 70% / 레어 25% / 슈퍼레어 5% (가중치는 실제
  아이템별 확률로 대체됨 — 이 수치는 데모용 예시)
- 슈퍼레어는 화면 플래시 + 파티클 양 증가로 임팩트 강조
- `prefers-reduced-motion` 사용자를 위해 애니메이션 축소/스킵 처리

## 7. 범위 밖 (Out of Scope, 이번 단계)

- 실제 결제(PG) 연동
- 실물 배송/재고 물류
- 네이티브 모바일 앱
- 출석 체크, 친구 초대 리워드 (Phase 2 후보)
- 상표 등록, 도메인 확보 (사용자 별도 진행)

## 8. 미해결 항목 (사용자 확인 필요)

- 마스코트 캐릭터 최종 이름 (몽글이 대체안 확정)
- `video.mp4` 실제 재생 길이/해상도 확인 및 웹 최적화 인코딩
- 배포 환경/도메인
